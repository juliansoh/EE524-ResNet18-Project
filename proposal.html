2. Planned Tiers

Build and optimize a correct ResNet-18 CUDA inference engine on the NVIDIA T4 GPU. The team will attempt to reach T4 (tensor cores), progressing through T0-T4 as defined on slide 15. Scope can be adjusted as the project progresses.

Tier / definitionPlanned implementation and evidence
T0 - BaselineBuild the starter; pass check.py; profile all 12 shape classes; select a batch size; submit the smoke-test entry.
T1 - Batched GEMM pathNHWC layout and batching; explicit im2col plus our own shared-memory-tiled SGEMM; bank-conflict-free tiles; fused bias/ReLU epilogues.
T2 - Implicit GEMMRemove the im2col buffer: compute input-gather addresses during tile loads; fuse the residual add; per-shape launch configurations.
T3 - Register tilingThread coarsening, 2-D block/register tiles (Boehm K4/K5), aligned float4 loads with safe edge handling, per-shape tile tuning.
T4 - Tensor cores (target)FP16 WMMA / mma.sync with FP32 accumulation and FP16 weights/activations; validate the reduced-precision path.
T5 - Fusion and tuningStretch only: fused stem/maxpool, shared downsample input reads, warp-shuffle avgpool/top-5, fewer launches, per-shape autotuning.

Roadmap. By the design specification (Dec 2): T1 and T2 on the FP32 leaderboard, with the T3 and T4 kernel designs in the specification. By the leaderboard freeze (Dec 15): T3 in FP32 (committed) and T4 in the FP16 category (target). T5 items only if time remains.

T0 baseline. Unmodified starter (conv=direct, FP32) on a Tesla T4: 18.6 images/s on the dev set (500 images, batch 32, median of 3 timed passes) and 13.8 images/s on the debug set (8 images, batch 8). Smoke-test package: Team-8_20261119T192840Z.zip.

Planned batch size: 64. Stage 4 gives only 49 GEMM rows per image. For a 512-channel stage-4 conv with 64×64 tiles, batch 8 gives 7×8 = 56 thread blocks for 40 SMs, but batch 64 gives 49×8 = 392. The T1 im2col buffer at batch 64 is about 462 MB, well inside the 16 GB on the T4. At each tier we will measure batch 32/64/128/256 on the T4 and submit the fastest.

4. Nsight Compute Profiling Plan

Profile representative kernels across all 12 shape classes at each tier, at the same batch size and precision. Keep each report. Confirm counter names on the T4 with ncu --query-metrics.

Metric / analysisSpecific counters; relevance
Roofline positionsm__throughput.avg.pct_of_peak_sustained_elapsed, dram__throughput.avg.pct_of_peak_sustained_elapsed; Speed Of Light roofline chart. Shows whether each kernel is compute-bound or memory-bound, and whether the tier moved it. Count an FMA as two FLOPs; use FP16 peaks for the tensor path.
DRAM trafficdram__bytes_read.sum, dram__bytes_write.sum. Gives arithmetic intensity (FLOP/byte); shows the tile reuse and the removal of the T1 im2col round trip at T2.
Shared-memory bank conflictsl1tex__data_bank_conflicts_pipe_lsu_mem_shared.sum. Must drop to near zero after padding or swizzling in the tiled GEMM.
Global-load coalescingl1tex__t_sectors_pipe_lsu_mem_global_op_ld.sum ÷ l1tex__t_requests_pipe_lsu_mem_global_op_ld.sum. Four sectors per request is ideal for aligned 32-bit warp loads; NHWC must get there.
L1 / L2 hit ratesl1tex__t_sector_hit_rate.pct, lts__t_sector_hit_rate.pct. Shows weight and activation reuse; read together with DRAM bytes and time, because a hit rate alone does not prove a speedup.
Achieved occupancysm__warps_active.avg.pct_of_peak_sustained_active. Registers, shared memory, and block size set it; T3 register tiling trades occupancy for ILP.
Warp stall reasonsWarp State Statistics section: long scoreboard (waiting on memory), MIO throttle (shared-memory pressure), barrier (sync imbalance). Names the bottleneck of each kernel.
Register pressure and spillslaunch__registers_per_thread, launch__shared_mem_per_block_static, l1tex__t_sectors_pipe_lsu_mem_local_op_ld.sum / _st.sum. Detects spills and occupancy loss from larger register tiles.
Tensor-core usesm__pipe_tensor_cycles_active.avg.pct_of_peak_sustained_active. Confirms that the T4 kernels keep the tensor pipe busy.
Time and speedupgpu__time_duration.sum per kernel; cudaEvent per layer or Nsight Systems for the layer breakdown. Optimize the three slowest shape classes, then measure again. Speedup = T0 time / optimized time for the same workload.

Isolate the timed region with cudaProfilerStart/cudaProfilerStop and --profile-from-start off. Measure scored images/s separately from instrumented NCU runs.

Validation

Validate each tier against the debug layer references, then the dev and full validation sets. Per-layer relative error: FP32 ≤ 10-3, FP16 ≤ 2×10-2; top-1 agreement ≥ 99.5%; top-1/top-5 label error within ±0.5 percentage points of the reference. All scored kernels are our own; no cuDNN, cuBLAS, or other GPU compute library.
